# EXP0053：独立运行时变体，非原生错误修复证明

在开启 EXP0053 的固定开发验证池之前登记，2026-10-04。

最终算法源仍为逐集群新检测修订后的版本。默认运行时出现：

- V4 完整预检中 `untrained / 1940000001` 返回 SIGILL (-4)。保留 3/4 完成和失败分母，不用调试回放替代。
- 修订后小训练检查中 `both / seed42 / scene_base1940000400 / 2048 steps` 返回 SIGSEGV (-11)，此前完成一个 1024 步 rollout 更新。
- gdb 重现了后一训练故障，捕获到 NumPy `_multiarray_umath` 中 `__svml_dcbrt_cout_rare_internal` / `array_subtract` 附近的 native 栈和指令。Python 栈位置不同，不能仅把根因归给物理接触计算，更不能凭此断言硬件损坏或 NumPy 上游缺陷。

根据 NumPy 官方 CPU 特性故障诊断思路，事先登记四次独立 2048 步复现（相同种子、源、场景）：默认设置两次，其中一次完成、一次 SIGSEGV；`NPY_DISABLE_CPU_FEATURES=AVX2,FMA3` 两次全部完成。这只是小样本诊断，不证明根因或永久稳定性。

## 接下来固定的运行时变体

- 对新的预检和整个试验的所有臂统一设置进程环境 `NPY_DISABLE_CPU_FEATURES=AVX2,FMA3`。不修改用户全局环境，不更新软件包，不改物理方程。
- 预检路径：`research/validation/EXP0053_TPG_PORTABLE_PREFLIGHT_20261004`，原先同两个预检场景，四次请求。全部成功且未训练/传统初始及最终状态一致，才启动新的开发试验。
- 开发试验路径：`research/validation/EXP0053_TPG_PORTABLE_STUDY_20261004`。仍是原登记的 9×8192 步训练和 52 次评估；所有模型从头训练，不复用此前权重，不调整原开发场景 1920000000–1920000003。
- 保存独立 `runtime_context.json`、源快照、所有请求、返回码及输出。该变体结果只适用于声明的运行时；不把它冒充默认运行时已通过。
- 任一新进程失败继续使本变体比较不通过，不通过删失败或不断补跑恢复分母。先前所有失败和中断仍保留在研究历史。
- 即使新矩阵完成，也不能声明旧原生问题已经查明或修复。需要后续最小复现、依赖/CPU 分发分析和独立稳定性验证。

## 实际结果：缓解未通过准入

该运行时变体的完整预检也只有 3/4 完成：`untrained / 1940000000` 返回 SIGSEGV (-11)，其余三次完成。源摘要均一致。两次短训练诊断成功不能升级成稳定性结论，不能用本批其余成功结果覆盖失败。

因此 **未启动** `EXP0053_TPG_PORTABLE_STUDY_20261004`，此前提到的 `EXP0053_TPG_STUDY_V2_20261004` 也未启动；9×8192/52 次开发主比较仍待运行时门槛解除。新入口 `scripts/run_tpg_runtime_study.py` 会拒绝失败预检，显式记录仅作用于子进程的运行时参数。该入口是可复现诊断工具，不是建议默认采用的已验证修复。
