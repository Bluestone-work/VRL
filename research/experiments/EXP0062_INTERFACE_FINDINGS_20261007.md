# EXP0062 接口审计：为什么继续 PPO / DAgger 没有转化为安全导航

日期：2026-10-07。来源均为本地代码和已有开发日志，不是临床安全结论。

## 1. 实际接口不存在“连续 Oracle → 离散 student”错位

`collect_oracle_dagger.py` 的 teacher 调用 `label_primitives`，逐个评估同一组 7 个动作。
teacher 和 student 都把动作索引交给 `primitive_local`，经同一 `Episode.step` 执行。
因此当前不应该凭猜测新增 trajectory-to-primitive 投影层；需要审计的是可见信息、成本及执行。

## 2. 标签一致，但区分度不足

保存成本审计：`research/validation/EXP0062_EVENT_LOCAL_20261007/oracle_interface_audit.json`。

| 数据轮次 | 样本数 | 第一/第二动作成本差中位数 | 差<0.05 的比例 | 恒停平均 regret | 恒前进平均 regret |
|---|---:|---:|---:|---:|---:|
| r0 | 15,747 | 0.0261 | 58.2% | 1.309 | 26.613 |
| r1 | 17,053 | 0.0233 | 61.4% | 1.635 | 36.300 |
| r2 | 15,113 | 0.0140 | 69.1% | 1.648 | 18.040 |

所有保存标签的成本均等于 argmin 成本。小成本差不是标签错误，但硬分类把大量近似等价行为
当成唯一答案；同时短视 regret 对停住很宽容。r2 验证准确率约 73.5%，实际闭环严格 Safe=1/84。
新完成的 r3 仍严格 Safe=1/84、任务=63/84，不应把分类准确率当作闭环改善。

`lookahead_teacher._score` 的 progress 是到 rollout 起点的欧氏位移，不是沿目标拓扑路径的进展；
逐步累计该起点位移也不是净进展。因此后续 teacher 应单独消融目标航段进展和任务剩余价值，
保持严重风险优先，不能通过削弱碰撞成本鼓励前进。

## 3. 观测与物理存在必须承认的缺口

- `VesselSDF` 来自健康术前半径，不是实时狭窄后有效管腔；局部匹配也可能滞后。
- `ImageSensor._render` 目前只加均匀 `background`，并未真的画出可分割的管腔边界。
  图像显示机器人和吸光障碍，但不能声称学生从这些图像直接看到真实管壁/当前狭窄半径。
- 障碍结构化框仍来自模拟检测（含噪、漏检、延迟）；不能称为已验证真实 YOLO 全链路。
- `mca_physical_dynamics._velocity` 对控制施加壁面间隙相关的 lubrication factor。
  简单的 velocity = flow + command 模型会把执行器减速误认为反向血流，造成错误抵消与停滞。

因此 Oracle 的仿真复制上界不能直接解释成在当前信息下 student 可达到的性能。

## 4. 本轮不接纳的方案

四解剖、各一个开发场景：

| Pilot | 做法 | 任务完成 | 壁接触均值 |
|---|---|---:|---:|
| baseline | 原 rule_switch + topo v3 | 4/4 | 2.660 s |
| v1 | 测量短视轨迹打分 | 2/4 | 56.166 s |
| v2 | 加参考动作、补偿等待、等待限时 | 2/4 | 53.892 s |
| v3 | 对整个控制向量作壁面投影/回正 | 2/4 | 67.724 s |
| v4 | 只修改横向修正、保留全局推进 | 4/4 | 2.617 s |

v1–v3 不能作为“效果提升”交付；代码快照与失败结果都保留。
v4 只是进入完整 84 场景检验的候选，pilot 差值不足以证明有效。
事件恢复把部分长连续接触拆开，但总接触、任务、安全失败必须同时报告，不能据此宣称安全改善。

## 5. 后续学习门槛

1. 先用完整配对结果决定是否保留新执行器；若回归则保持原基线，不自动替换。
2. 下一轮 teacher 只改评价：安全成本不减、航段进展替代欧氏漂移、对长期等待评估剩余价值。
3. 报告近障碍子集的避障召回、危险动作 regret、停止占比和闭环任务，不仅总体准确率。
4. 增加真实可见的局部管腔观测应作为独立感知实验，对所有对照使用同样新传感器。
5. 所有动作/传感器/teacher 版本写入数据与 checkpoint，旧权重不得直接复用新语义。
