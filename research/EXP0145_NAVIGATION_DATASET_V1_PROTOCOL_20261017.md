# EXP0145 — navigation dataset v1

## Why the previous `unseen` score could exceed `seen`

The K13 diagnostic used only about 18 seen and 10 unseen episodes per report, and the two groups were not a paired factorial grid. Their anatomy, flow, obstacle layout, clot placement, and seed composition therefore differed. A higher pooled unseen mean can result from easier sampled layouts or ordinary seed variance; it is not evidence that the policy generalizes better. The three training seeds also had substantial variance (final success 75.0–77.8%). Those results remain development diagnostics, not a sealed comparison.

The new manifest fixes this by freezing the same condition grid and separating scene seeds by split. Results must be reported by anatomy, cluster count, flow mode, clot pattern, obstacle density, and obstacle layout before pooled summaries are shown.

## Registered scenario grid

The dataset is described by `configs/navigation_dataset_v1.json` and generated by `scripts/build_navigation_dataset.py`. It contains 14 registered anatomies, `N ∈ {1,2,3}`, three flow modes, three clot patterns, four dynamic-obstacle densities, and two obstacle layouts:

- weak: healthy-inlet mean-speed simulator unit `0.025 mm/s`, steady;
- strong: `0.1 mm/s`, steady;
- pulsatile: nominal `0.05 mm/s`, episode-level `Variation(strength=0.75, pulsatile=True)`; mean flow and waveform parameters are sampled at reset and remain fixed for that episode;
- clot patterns: `historical_sites`, `random_branches`, and deterministic per-scene `mixed_pattern` realizations;
- obstacle densities: 4, 8, 16, and 32 dynamic particles; `uniform` and `route_encounter` layouts.

The flow values are simulator healthy-inlet mean-speed inputs used by `LysisEpisode(flow_inlet_mm_s=...)`; they are not clinical measurements. The existing spatial flow field and within-episode pulsation remain active. The actor receives deployable observations only; true flow, response gain, anatomy ID, and simulator positions are not manifest observations.

Each condition has 20 scene replicates. The frozen manifest has 72 condition combinations and 60,480 rows after crossing cluster count. Scene seeds are paired across `N` and methods by reusing the row's `scene_seed`; accepted reset seeds and the final physical `scenario_hash` must be recorded by the runner.

## Split protocol

The nine registered training anatomies are split into 16 train and 4 validation scene replicates per condition. Five anatomies are held out in full (all cluster counts and all conditions) for the zero-shot challenge test, with 20 replicates per condition:

`coronary_rca`, `basilar_vertebral`, `cerebral_venous_sinus`, `sma_embolism`, `femoropopliteal_pad`.

Train, validation, and holdout seeds use independent namespaces beginning at 3.4e9, 3.5e9, and 3.6e9. These are outside the registered evaluation pools and the previously accessed 2.7e9 multicluster development namespace. The manifest hash is recorded in `research/datasets/NAVIGATION_V1/metadata.json` and must be reported with every experiment.

The holdout set is not used for model selection. The `0.15 mm/s` range-outside pressure condition is intentionally not mixed into this ordinary manifest; it is an additional stress protocol after the method is frozen.

## Reproduction

```bash
python scripts/build_navigation_dataset.py --output
python scripts/build_navigation_dataset.py --check
sha256sum research/datasets/NAVIGATION_V1/manifest.jsonl
```

The builder validates anatomy coverage, row counts, unique scenario hashes, and cross-split seed disjointness. It creates a scenario catalogue rather than pre-simulated trajectories; training and evaluation runners must preserve the row fields and append reset acceptance records plus raw per-episode metrics.

Dataset-driven IPPO/ISAC/DQN training can be started with a bounded pilot before a long run:

```bash
python scripts/train_sb3_ippo.py --out research/runs/NAVIGATION_V1/IPPO_s41 \
  --dataset-split train --dataset-limit 512 --clusters 3 --timesteps 1000000
python scripts/train_sb3_isac.py --out research/runs/NAVIGATION_V1/ISAC_s41 \
  --dataset-split train --dataset-limit 512 --clusters 3 --timesteps 1000000
python scripts/train_discrete_rl.py --algorithm dqn --out research/runs/NAVIGATION_V1/DQN_s41 \
  --dataset-split train --dataset-limit 512 --clusters 3 --timesteps 1000000
python scripts/evaluate_navigation_dataset.py --model <checkpoint.zip> --kind ppo \
  --split validation --clusters 3 --max-episodes 0 --out <validation.json>
python scripts/evaluate_navigation_dataset.py --model <checkpoint.zip> --kind ppo \
  --split holdout_test --clusters 3 --max-episodes 0 --out <holdout.json>
```

`--dataset-limit` limits the catalogue used by a pilot; it does not alter the frozen manifest. Holdout evaluation is a separate command and is never consumed by training or checkpoint selection.
